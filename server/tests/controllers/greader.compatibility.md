# Google Reader compatibility characterization

This suite is a safety net for the currently mounted RSSMonster Google Reader API.
Passing tests prefixed with `[current]` describe behavior observed through Express,
the real Sequelize models, and MySQL. They are not claims that the behavior is
Google Reader-compatible.

Tests prefixed with `[compatibility gap]` are skipped requirements whose expected
Google Reader behavior is clear but differs from RSSMonster today. Tests prefixed
with `[product decision]` stay skipped until the product contract is chosen.

| Area | Current RSSMonster behavior | Google Reader-compatible target | Status |
| --- | --- | --- | --- |
| ClientLogin | Returns exact `SID`, `LSID=null`, and `Auth` text lines; invalid or incomplete credentials are rejected. | Preserve the wire-format response. | Characterized |
| Auth header | Accepts `GoogleLogin auth=` and the intentional `GoogleLogin_auth=` legacy form. | Preserve both while supported. | Characterized |
| Unauthorized response | Authentication and action-token failures return text/plain HTTP 401 with `Google-Bad-Token: true` and the same body. | Preserve the non-enumerating failure contract. | Characterized |
| Username parsing | Parses the credential against the exact 64-character RSSMonster token suffix, so permitted usernames containing `/` authenticate safely. | Preserve delimiter-safe parsing. | Characterized |
| Action token | Returns a stable, domain-separated 57-character HMAC-derived token plus a newline. All mutation routes validate `T`. | Preserve exact length, credential binding, and mutation validation. | Characterized |
| Repeated parameters | A shared normalizer preserves strings and Express arrays from both URL-encoded bodies and query strings. Repeated `s`, `i`, `a`, `r`, `it`, and `xt` values are retained in source order. | Preserve every supplied value without body/query overwrites. | Characterized |
| GET mutation compatibility | The intentional GET `subscription/edit` route remains available and requires `T` through the query string. | Prefer POST while retaining this existing client-compatibility route. | Characterized |
| Streams | Canonical, unfiltered articles are sorted and keyset-paginated by `publishedAt` and ID. `ot`, `nt`, and `crawlTimeMsec` use immutable ingestion `createdAt`; published fields use publisher `publishedAt`. Unknown targets, conflicting path/query targets, malformed continuations, and invalid counts return HTTP 400. | Preserve deterministic pagination and the crawl-time/publication-time distinction. | Characterized |
| Stream counts | Missing `n` defaults to 20. Content streams are clamped to 1000, while `stream/items/ids` permits up to 10000 IDs for Reeder state reconciliation. Negative, fractional, conflicting, and malformed values are rejected. | Keep content queries bounded without truncating client state synchronization. | Characterized |
| Stream target composition | Repeated primary `s` targets form a union. Repeated `it` targets are intersected and every `xt` target is excluded. Contradictory filters deterministically return an empty population. | Preserve explicit compositional behavior. | Characterized |
| Item IDs | ID listings retain their decimal compatibility contract. Serialized articles use exact 16-character lowercase hexadecimal item IDs. Content lookup accepts positive decimal IDs and exact full IDs within the signed MySQL `INTEGER` range, rejecting malformed, unsafe, negative, zero, or overflowing values. | Preserve strict full-input validation. | Characterized |
| Duplicate requested IDs | Content lookup deduplicates equivalent decimal/full IDs while preserving first-occurrence order. | Preserve deterministic first-occurrence behavior. | Characterized |
| Unread counts | One grouped article aggregate supplies per-feed unread counts and newest immutable `createdAt` crawl timestamps; feed/category metadata queries preserve zero-count rows. Category and reading-list values are composed from those aggregates. `max` is the authenticated user's total canonical unread count, not a server cap. | Preserve bounded query count, user scoping, canonical filtering, zero rows, and the total-count meaning of `max`. | Characterized |
| Mutations | `edit-tag` computes one final update and applies it transactionally to user-owned canonical, unfiltered IDs. Remove wins add/remove conflicts; unknown state tags are ignored; empty ID lists are successful no-ops and malformed IDs return HTTP 400. Read/unread synchronizes `readAt`. `mark-all-as-read` reuses stream scope, compares Reader timestamps to immutable `createdAt`, updates only unread rows, and preserves existing `readAt` values. | Preserve deterministic state transitions, atomicity, and crawl-time scoping. | Characterized |
| Existing subscription | A repeated subscribe returns `OK` without creating a duplicate and applies an explicitly supplied title or category. | Preserve idempotency while honoring explicit metadata changes. | Characterized |
| OPML import | Multipart `subscriptions_file` uploads are held in memory, limited to 1 MiB, and selected subscriptions are normalized, duplicate-checked, and stored without requiring outbound discovery. The response is `text/plain` `OK`. | Preserve transactional duplicate handling and never write client filenames. | Characterized |
| Repeated subscription categories | The first valid repeated `a` category is used, and `a` deterministically wins when both `a` and `r` are supplied. Removing without adding moves the feed to the concurrency-safe `Uncategorized` default. | Preserve the single-category model deterministically. | Characterized |
| Category operations | Rename collisions merge source feeds into the existing destination atomically. Repeated disable `s` values are processed in one transaction and move feeds to the single established `Uncategorized` category. | Keep feed categories distinct from article labels. | Characterized |
| Article labels | RSSMonster Tag rows mix derived and manual provenance under one per-article name uniqueness constraint. Reader label mutation is therefore not mapped onto Tag rows, and unknown edit-tag labels remain ignored. | Requires a product/data-model decision before support can avoid destroying derived metadata. | Explicitly unsupported |
| HTTP behavior | Reader responses are `no-store, private`; application CORS handles Authorization preflight; compatibility check returns clear PASS/FAIL header-forwarding results; internal errors use a stable generic text response. | Preserve centralized rate limiting and non-disclosing errors. | Characterized |
| Serialization time units | `crawlTimeMsec` is milliseconds, `timestampUsec` is microseconds, and `published` is seconds. | Preserve the distinct units. | Characterized |
| Null dates | `firstSeen` does not affect protocol crawl time. Null legacy `createdAt` serializes as the Unix epoch and is excluded by bounded `ot`/`nt` SQL predicates; `publishedAt` is non-null by model and database contract. | Preserve deterministic handling and decide whether legacy null `publishedAt` rows require repair. | Characterized; legacy publication repair is a product decision |
| Content | Serialization returns persisted sanitized `contentHtml` without truncation. Missing display HTML becomes an empty string; raw description and `contentOriginal` are not reintroduced. | Preserve the ingestion sanitizer boundary. | Characterized |
| Origin URL | `origin.streamId` uses the subscription URL and `origin.title` uses the feed title. `origin.htmlUrl` is empty because Feed has no publisher-site field; the subscription URL is not fabricated as a homepage. | Populate `htmlUrl` only after a real publisher-site field exists. | Characterized |
